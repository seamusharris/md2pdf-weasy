# Migrating rendering from v0.1.0

The stabilized renderer is compatible with v0.1.0 content, with one
intentional default presentation change: eligible undeclared tables now get
deterministic typed column widths. A synthetic, locally reproducible matrix
compares the immutable `v0.1.0` tag at commit
`f565357a9e6ba975ae9e1699f27be876825b149e` with the current renderer.

The machine-readable decision is
[`compatibility/v0.1.0-rendering.json`](compatibility/v0.1.0-rendering.json).
Current visual quality remains governed by the independent T-009 acceptance
manifest with digest
`279ce1b06ea7bf656a32c2f2c9a1480f0d552449209b0348ab2469a62ef59ce7`.

## Observed differences

| Observation | Classification | Evidence / control |
|---|---|---|
| Eligible undeclared schedules gain typed colgroups and may wrap differently. | Intentional | `automatic-widths-intentional`; use `table_widths: false` for a document-level fallback. |
| Cell text, order, captions, IDs, scopes, and `headers` associations remain intact. | Compatible | `content-preserved` and `semantics-preserved`. v0.1.0's date-dash typography is normalized only for this logical-content comparison; exact HTML hashes remain recorded. |
| A matching `tables:` layout keeps its declared percentage widths. | Compatible control | `declared-layout-precedence`; prefer this for an exact full-table contract. |
| An author-supplied `<colgroup>` remains unchanged. | Compatible control | `author-colgroup-precedence`. |
| A supported `columns: {Venue: 12em}` override pins one eligible column. | Compatible control | `explicit-venue-width`. |
| Content loss/reordering, clipping, semantic loss, precedence failure, or automatic markup surviving the opt-out. | Regression / blocker | Any corresponding check fails and prevents a successful compatibility decision. |

## Staged migration

1. Render the document unchanged and compare it with your known-good PDF.
2. If only automatic table sizing is unsuitable, add the narrow fallback:

   ```yaml
   ---
   table_widths: false
   ---
   ```

   The case-insensitive aliases `off`, `none`, and `legacy` are equivalent.
3. For an exact percentage contract, declare the complete header-matched
   layout under `tables:`. Declared layouts and author colgroups take
   precedence over automation.
4. For one eligible automatic column, use a positive finite numeric em value
   or positive decimal `em` string:

   ```yaml
   columns:
     Venue: 12em
   ```

The opt-out suppresses only the automatic-width pass. It does not revert
PDF/UA tagging, language metadata, fonts, stylesheets, dependency behavior,
typography, or unrelated correctness fixes. Validate private documents in
their own locked environment; repository evidence is deliberately synthetic
and contains no consumer data.

## Full rollback

If the narrower controls cannot meet an emergency requirement, pin both the
tag and its attested commit in your private distribution workflow:

```bash
pip install "md2pdf-weasy @ git+ssh://git@github.com/seamusharris/md2pdf-weasy.git@f565357a9e6ba975ae9e1699f27be876825b149e"
```

Retain the consumer's known-good Python dependency lock and native
WeasyPrint/Pango/Cairo environment. This remains a private package with
non-redistributable bundled fonts; do not publish its wheel or source archive.

### Accessibility warning

A full tag rollback is not a width rollback. v0.1.0 hard-codes English HTML
and does not request PDF/UA-1; the current renderer records the document's
language and emits marked, structured PDF/UA output. After any rollback,
revalidate screen-reader reading order, table/header associations, document
language and title, text contrast, and semantic-colour cues on the actual
consumer PDFs. Prefer `table_widths: false` or declared layouts because those
retain the current accessibility behavior.

## Reproduce and recover

From a clean local clone containing the attested tag, using the project's
canonical virtual environment and installed Poppler:

```bash
make compatibility-v0.1
make compatibility-v0.1-verify CANDIDATE=output/pdf/compatibility-v0.1/candidates/<candidate>
make compatibility-v0.1-concurrency
```

The concurrency target is the explicit real-render acceptance: it runs two
complete generators together and verifies that their structural and raster
evidence is complete, isolated, and deterministic. The ordinary unit suite
keeps this historical-tag execution opt-in.

A successful candidate is based on the immutable renderer snapshot, source
hashes, base commit, historical tag commit, and content-addressed T-009 visual
digest captured in its signed manifest. It does not claim that the mutable
checkout is still identical at the instant of publication; verification makes
that separate freshness check and reports a later edit as stale evidence.
`pending.json` is atomically renamed to `success.json` only after the snapshot
evidence is complete. Any `failure.json` marker takes precedence, so
interrupted cleanup cannot make a failed generation appear successful.

The command uses only local Git objects, writes raw HTML/PDF/page images below
the ignored candidate directory, and never changes a worktree or installs a
dependency. Return to the stabilized checkout by reinstalling your pinned
current commit, rerendering, and removing old bounded candidates with:

```bash
make compatibility-v0.1-prune
```
